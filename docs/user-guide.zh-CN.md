# HubFetch 用户指南（简体中文）

HubFetch 是一个非官方、由社区构建的 Hugging Face Hub Windows 桌面客户端。它与 Hugging Face,
Inc. **无任何关联，也未获得其认可或赞助**。

本指南将引导您完成安装、登录、下载、克隆以及配置 HubFetch 的完整流程。

## 概述

HubFetch 让您可以浏览 Hugging Face Hub、将模型和数据集下载到标准 HF 缓存中、通过真正的 Git
将仓库克隆为工作副本，并在一个应用中管理您的 Hub 工作流。它注重隐私：没有任何遥测，您的令牌在
静态存储时会被加密。

## 安装

1. 从 [GitHub Releases](https://github.com/OranImp/HubFetch/releases) 下载
   `HubFetch-<version>-windows-x64.zip`。
2. 将 ZIP 解压到您选择的文件夹。
3. 运行 `HubFetch.exe`。

该 ZIP 是**未签名**的。Windows SmartScreen 在首次启动时可能显示警告；请选择
**更多信息 → 仍要运行**，并对照发布的 SHA-256 校验和验证 ZIP。没有安装程序，也没有自动更新——
如需更新，请下载更新的版本并替换文件。

系统要求：Windows x64。要使用克隆功能，必须安装 **Git**（对于使用 Xet 的仓库还需要
**Git-Xet**）并将其加入 `PATH`。HubFetch **不随附**这些工具；请打开 **设置 → Clone tools**
检查就绪状态，并在缺少工具时前往其**官方下载页**。

## 登录

打开 **设置 → 账户** 并粘贴
[User Access Token](https://huggingface.co/settings/tokens)。建议使用**写入**令牌（或具有所需
权限的细粒度令牌），以便受限下载、讨论、合集和 Hub 通知都能正常工作。令牌会使用您的操作系统
密钥链加密，并存储在 `%APPDATA%\HubFetch\credentials.json` 中；绝不会以明文或 `localStorage`
形式存储。

您还可以通过应用捕获 Hub Web 会话，从而启用基于 Cookie 的社交功能（帖子、表情回应以及其他
写入操作）。

## 浏览

- **浏览** 页面以三栏布局展示模型、数据集、Spaces 和每日论文。
- 按 `Cmd/Ctrl+K` 打开命令面板，进行搜索、筛选和排序。
- 点击仓库即可查看其模型卡片、文件树、元数据和讨论。
- 使用 **对比** 并排查看 2–4 个模型。

## 下载

- 打开一个仓库并开始下载，或使用下载管理器排队和调度传输。
- 下载**并行且可恢复**，支持**限速**，并使用 **SHA-256** 校验文件。
- 文件落在**标准 HF 缓存布局**中，因此可与 `transformers`、`huggingface-cli` 以及其他工具
  互操作。
- 下载与克隆是相互独立的子系统，具有各自的并发能力；暂停或取消下载不会影响克隆任务。

## 克隆

HubFetch 通过**系统 Git**（当仓库使用 Xet 过滤器时还包括**系统 Git-Xet**）将仓库克隆为真正的
Git 工作副本。

- 克隆在持久化调度器下**一次运行一个**。
- 您可以克隆分支、标签或完整提交；会显示进度，并且在**重启后恢复**未完成的工作。
- **前置条件**：在首次克隆前，请打开 **设置 → Clone tools** 并检查 Git、Git-Xet 和 Git 凭据
  管理器行。缺少的工具会链接到其**官方下载页**；安装完成后点击**重新检查**——如果仍提示缺少
  工具，请重启 HubFetch。
- **身份验证**：Git 克隆通过系统 Git（Git Credential Manager / SSH）进行身份验证，或者对于
  应用令牌克隆，通过受 Job 约束的安全 AskPass 辅助程序进行。辅助程序绝不会将令牌写入磁盘。
- 如果缺少 Git 或 Git-Xet，诊断页面会报告就绪状态，方便您先行修复。

## 代理

网络设置提供三种封闭模式：

- **系统** — 继承操作系统代理配置（默认）。
- **直连** — 完全绕过环境、Chromium 和 Git 配置中的代理。
- **手动** — 使用特定的 HTTP/HTTPS 代理 URL。

该选择同时适用于 Hub API 流量和 Git 克隆子进程。详见 [architecture.md](architecture.md#proxy-semantics)。

## 诊断与支持包

打开**诊断**页面可查看缓存/磁盘健康状况、Git 和 Git-Xet 就绪状态、凭据辅助程序和 SSH 可用性、
端点可达性以及代理状态。

使用 **导出支持包** 生成一个经过脱敏的 ZIP，其中包含已清理的日志和结构化状态，便于在缺陷报告中
分享。密钥会在中心位置统一脱敏；如果任何已注册的密钥泄露，导出将自动失败。

## 通知

HubFetch 可以针对传输完成以及关注/收件箱和每日论文更新显示系统通知。请在**设置**中启用或禁用。
通知完全在本地进行，不会向任何第三方发送任何内容。

## 设置

在**设置**中，您可以管理：语言（九种区域设置）、主题（系统/浅色/深色）、下载并发与限速、通知、
轮询间隔、UI 缩放与密度、强调色、缓存目录、Hub 端点、代理、登录时启动、关闭到托盘以及按仓库
的打开目标。

**Clone tools**（位于"连接"下）会显示 Git、Git-Xet 和 Git 凭据管理器的就绪状态，并提供指向其
**官方下载页**的链接。安装后请点击**重新检查**；如果仍提示缺少工具，请重启 HubFetch。

您可以**导出**和**导入**设置（不包括特定机器的缓存目录），以便在多台机器之间迁移。

## 隐私与数据

- 您的令牌和 Hub Web 会话在静态存储时会被加密，绝不会被记录。
- 浏览历史、收藏、关注、下载任务和克隆状态均以 SQLite 形式本地存储。
- 您可以在设置中使用**清除本地数据**（收藏、历史、下载、关注、收件箱）并退出登录；也可以删除
  凭据文件以在所有位置退出登录。

## 故障排除

有关常见问题，请参阅 [troubleshooting.md](troubleshooting.md)：SmartScreen 警告、找不到
Git/Git-Xet、代理连接失败，以及如何收集支持包。
